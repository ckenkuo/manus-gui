# 2026-09-09 发布失败修复

涉及错误：尺码表缺少宽/净重/长、SKU 预览图处理失败、保存要求上传预览图或选择站点仓库、描述编辑器打开失败，以及 Temu/1688 采集失败。

- 尺码表读取、填充都排除 Ant Design 的隐藏测量行，并支持表头和表体分属不同 table。尺码单元格有输入框时读取其值，避免把辅助行 `size` 当成商品尺码。源尺寸即使无法与页面尺码对齐，也保留为估算参考，不任意选择小号/大号代替均码。模型输出缺行、缺参数或非有效正数会触发一次纠正重试，最终仍缺数据则停止填表。
- SKU 预览图按每行入口处理：有悬停菜单时替换，有点击图格时补图或替换。整表没有悬停入口不再导致跳过空图。图片加载和替换回读有有限等待，空图、不合规图和持续无法加载的图都不会报告成功。
- 仓库校验同时检查选中项及实际生成的库存列，点击后重新查询 DOM。仓库名称只允许明确的“仓/仓库”后缀归一，避免短名称误匹配其他仓库。保存前再次检查仓库及预览图；仓库失效要求重跑库存阶段，避免保存时补选仓库却遗漏新库存列。
- 描述编辑器打开后最多轮询 10 秒，识别到可见编辑器即继续，失败记录当前 URL。
- Temu 必须同时获得商品 ID 和标题才判定数据就绪，核对商品 ID，登录等待期间重新查找用户新开的商品页。页签复用排除带目标链接参数的登录页，兼容 `/g-ID.html` 和 `-g-ID.html`。
- 1688 诊断分别报告 context 缺失、result 缺失和 data 缺失，附带 URL/页面标题/加载状态，避免空对象兜底产生错误的 `hasResult=True`。

站点仓库说明：从店小秘当前页面脚本可见，库存区“选择仓库”更新 `warehouseSites`，保存通过同一数据生成的库存列判断是否选择站点仓库；并非另一个需要独立填写的字段。

重试方式：重启加载旧模块的发布进程，再续跑失败商品。平台登录或人机验证仍需在该 Chrome 窗口完成；程序会等待并在目标商品数据就绪后继续。本次不改变平台登录状态，不自动提交商品发布。

回归用例位于 `tests/test_publish_error_recovery.py`，使用离线 DOM 与模拟模型/浏览器，无商品保存、发布或告警发送。
