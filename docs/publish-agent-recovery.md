# 发布失败的 Manus ReAct 兜底

1688、拼多多、Temu、Amazon 的发布流程共用阶段执行器。阶段返回失败或抛出异常时，自动把错误、商品上下文和当前 CDP 会话交给 Manus。每个失败阶段最多启动一次兜底，最多 16 个 ReAct 步骤、600 秒。

`app/publish/agent_tools.py` 将 `pipeline.py` 公开导出的异步页面函数注册为独立的 `dxm_*` 工具，包括类目、属性、标题、素材图、SKC、预览图、尺码、尺码表、货号、变种、库存、仓库、运输、描述和视频。另有类目列/属性下拉等细粒度工具，以及观察页面、读取源商品 product-info.json、截图、JavaScript、鼠标和 CDP 键盘输入工具。新增到兼容入口的公开页面函数会自动注册。

工具使用原来的会话；商品 ID、数据文件路径、店铺、站点、仓库由任务注入，模型不能通过函数参数替换。每次兜底使用独立 Manus 实例，沿用 Manus 默认模型配置，不连接额外 MCP 服务，也不关闭管线拥有的浏览器。

`dxm_stage_<阶段>` 执行原流程阶段及其校验，保留原上下文回写。只提供当前及此前阶段。修复后必须执行失败阶段对应的工具；模型自行宣称成功不算通过。后续页面工具调用会使之前的验证失效。

阶段④ 属性审核在必填属性仍留空时如实判失败（不再只发人工提示放过，否则会白跑十几个阶段到⑭保存才暴露），因此该场景现在也会走兜底：agent 读源商品信息、用属性下拉工具补选，再复跑 `dxm_stage_attrs` 复验；补不上则商品在④终止并保留属性页现场。

保存和发布通过阶段工具执行，保留仓库、预览图、保存状态和 `do_publish` 校验。发布兜底先读列表：已在线则结束；确认仍在草稿或发布失败列表才允许重试；结果不明时保持失败，避免重复提交。JavaScript 和通用点击工具仍具有页面修改能力，不能视作权限沙箱；提示词要求保存/发布只能使用阶段工具。

恢复通过后继续后续阶段；失败、超时或模型不可用时保留原失败信息和编辑现场。用户取消会直接传播，不启动下一轮恢复。CDP 已断开时不启动 agent，沿用批次已有的重连处理。来源身份校验等执行前校验不交给模型绕过。

工具调用摘要输出到现有进度日志；原失败、恢复结果和工具历史写入断点文件的 `stages.<阶段>.recovery`。恢复不会修改批次参数或自动开启发布。

离线验证：`.venv/Scripts/python.exe -m pytest tests/test_publish_agent_recovery.py tests/test_publish_workflows.py tests/test_publish_service.py`。
