# 活动管理的 WPS 数据源

打开 `/activity`，选择已保存的金山文档或粘贴在线表格分享链接，点击「读取文档」，再选择工作表。
新粘贴的链接可填写可选的文档名称，点击「保存链接」加入已保存文档列表，无需先读取工作表。
同一链接再次保存可更新名称；保存结果会立即显示，重新打开页面后仍可从列表选择。
程序复用已登录的 `kdocs-cli` 读取在线数据，不下载或读取本地 Excel，也不修改源文档。
未登录或无权限时，页面会显示读取错误；需先在运行服务的同一用户下完成 `kdocs-cli` 登录。

页面展示工作表的单元格文本、原始行号和数据检查结果，支持全文搜索、每页 50 行浏览、单品勾选及选择全部筛选结果。
列表筛选支持按字段选择条件：文本列提供包含/不包含/等于/开头是，价格、重量、折扣等数字列提供等于、≥、≤、>、<。
可添加多个条件，并切换为“同时满足”或“任一满足”；筛选只改变展示结果，不会改变 WPS 文档。
切换文档、工作表或刷新会清空选择；选择按 SPU 去重。浏览器保存最近成功读取的文档和工作表。

活动需要 `SPU`、`日常价`、`销售价/销售价格/售价` 三列，表头从前 10 行识别，列顺序不固定。
公式读取 WPS 当前计算结果；空值、错误结果、非正数价格或非完整数字 SPU 不可选择。
一个 SPU 可占多行（每行一个货号，各自日常价/底价不同是合法场景）：SPU 列的纵向合并单元格
会展开补齐到每个货号行；价格列即使合并也不继承——任一货号行价格为空/无效，或同一货号
重复出现，整个 SPU 都不可选择，需要先修正文档。活动入选要求全部货号的申报价都达各自底价。

**申报价口径**：申报价 = 日常价 × 活动折扣率，结果**向下取整到分**——与平台参考价同口径。
实测（2026-09-24）平台的参考价就是「平台日常价 × 折扣率向下取整」：188.88×0.85 = 160.548
平台给 160.54、163.23×0.85 = 138.7455 平台给 138.74。用四舍五入时第三位小数 ≥5（约占一半）
的商品申报价会比上限高 1 分、必被平台拒；改向下取整后不会再因 1 分差报不上。代价是极少数
情况少报 1 分；换来的是底价高于平台上限的活动在**初筛阶段**就被判「不达底价」（矩阵里直接
看得到），而不是等填价时才失败。

执行时提报页的价格行是平台 SKC 粒度（款式×尺码），同一货号的多个款式各占一行（实测 3 个
货号的商品出现 6 个价格行），故逐行配对到成本表货号后填各自申报价。**配对键：先平台货号
（归一化后与表比对），配不齐再退回日常价**——用户规则「日常价以表为准」（2026-09-24）：
平台显示的日常价可能过期，不能因为与表不一致就整单不报（实测过表写 163.23、平台显示 188.88
被整单拦下）。填价只填**空**的输入框（同一行还有预填了库存数的输入框，取「第一个输入框」
会把价格填进库存），写完回读校验，读回不一致按填价失败处理。
页面货号与日常价**两条键都对不上**、或有货号没有任何行覆盖时，一行不填、不提交。
加速器同理，按货号文本把对话框行归属到成本表货号，归属不明则中止不开。
其他列也以文本展示；嵌入图片暂不渲染。当前最多读取 40 列、表头后 20,000 行，每次分段读取 500 行。

「开始」默认仅生成活动计划。服务端会重新读取云端所选 SPU 的价格，不使用浏览器传入的价格；
如果商品已删除或价格失效，整批在访问 Temu 前中止。正式报名仍由原有的「正式执行」开关控制。
文档更新后建议先刷新核对；开始时使用的是重新读取到的价格。

商品采用实时采购，活动初筛只判断申报价是否达到销售底价，不读取库存、不因库存不足或未知跳过。
平台库存要求仅作展示，进入活动详情后仍按平台返回的商品报名资格处理。
列表页可报名、点进详情却搜不到该 SPU 属平台的正常业务结果（外部资格与详情资格不同），
按 info 记录并跳过该活动，不计入失败。

## 识别矩阵（先看清「哪个商品能报哪个活动」）

「识别」是**只读**扫描：读一次成本表与活动列表，逐（商品×活动）开一次提报页搜索判资格，
不勾选、不设场次、不填价、不提交、不碰流量，随时可重跑。

- 矩阵格子分两层结论：**价格层**（申报价是否达该货号底价，本地算，含未达底价的格子）与
  **资格层**（平台详情页是否真有资格，必须开页探测）。价格层随扫描开始一次性下发，资格层逐格点亮。
- 只对价格初筛**通过**的格子做资格探测；一个候选都没有的活动不开提报页（活动页有近百个活动）。
- 结果落盘 `活动识别矩阵/activity-matrix-<日期>.json`（桌面输出目录，不可写时回退 workspace）。
- 勾选「执行选中」时只报勾选的格子；一格都没勾的商品**连流量都不动**。
- 执行档位：**半程**（开提报页填价，不提交、不真关/开流量，可逆）与**全程**（真提交/真关/真开）。

## 当天缓存与作废

资格探测每格 10~20 秒，故当天复用：文件按天切，命中缓存的格子直接回填、不再开页；
价格层每次从成本表重算，折扣率或日常价改了自动反映。要点：

- 缓存**只存客观事实**（eligible 真/假 + 扫描时间），fail-closed（超时/开页失败）**不落盘**，下次重探。
- 跨 24:00 作废：活动按期数轮换，跨天复用会拿到过期资格。页面上标明「识别于 …（仅当天有效）」。
- 活动下架（期数换轮）时整列丢弃；新出现的活动自动回到「待识别」。
- 勾「强制重扫」忽略缓存全量重探。
- 刷新页面回读当天文件（不连 CDP、不读成本表）；若文件来自另一份文档/工作表，页面提示重新识别。

## 暂停与逐格跳过

- **暂停可恢复**：在当前动作收尾后的安全边界挂起（商品之间、活动之间），点「继续」接着跑。
  挂起期间不会点任何按钮，也不会留下半开的提报页。
- **收尾阶段（重开流量）拒绝暂停**：此刻流量已关，挂起等于商品在无流量状态下卖货。
  接口返回 409，页面提示并自动继续——只要关过流量，就一定跑到恢复。
- **逐格跳过**：执行中在「报名计划」表按行跳过某个（商品，活动）。跳过的格子不填价、不提交、
  也不参与报名记录对账（不产生「未查到成功记录」的假失败）。已填价的格子拒绝跳过——
  本活动的报名是一次提交全部已填商品，反填不回来，请到提报页手动取消勾选。
- 跳过是**活动粒度**：该商品的流量若已被关闭，阶段三仍会重开（跳过不等于不开流量）。
- 识别扫描与正式执行**互斥**（同一时间只能有一个占用提报页）：两者都靠新开页签的对象身份
  识别自己的页面，并发会互相认错页、把资格记到别的活动名下。纯 dry-run 批次不开提报页，不受限。
- 加速器入口文案随商品状态变：待开启是「立即开启」，待关注（加速器列写「商品流量待关注 /
  您可加速提效」）是「**报名流量加速器**」。两个都按顺序试，命中即用；都找不到时把加速器列的
  现场文本写进 note，便于区分「平台没给入口」与「页面结构变了」。
- 流量页的大表是**左右分栏渲染**：SPU 信息列与操作列不在同一 DOM 子树里，按「含 SPU ID 的容器」
  找操作会漏；操作定位按**纵向坐标对齐**（同一条视觉带）兜底。
- **开启加速器后平台生效有延迟**（实测约半小时：点「立即加速」拿到成功提示，半小时内回查该行
  仍是「开启流量加速器 / 立即开启」，之后才变「流量加速中」）。所以判成功以**平台受理提示**为准，
  同时把「回查尚未生效」如实写进 note，不要拿即时回查当判据（会误判未开、还会整轮重试反复点）。
- **加速器开着（含未生效但已设价）时前端售价按加速价** → 活动的申报上限被压低到
  「加速价 × 活动折扣」，按成本表日常价算的申报价必然超高被平台拒。而平台对已开启的加速器有
  **24 小时锁定期**（关闭请求会被拒：「加速器开启后需满24小时才可手动关闭」），锁定期内该商品
  报不了活动——失败文案会直说这条因果，并点出「平台认可日常价」与哪个货号的加速价吻合。
- 「调整申报价」对话框按**日常价档**列行（不是一个货号一行）：同一档的多个货号只能填一个价，
  取该档**最高传入价**（逐货号 = max(底价+1, 活动申报价÷0.9 向上取整)，同档取最高）。行的身份键是
  「参考申报价格 + 让价」= 该档日常价（实测 30.27+44.45=74.72、168.67+20.21=188.88）。
  **分档用的是平台侧日常价**（本次提报页读到的），表里的日常价只用来算钱——两者可能不一致
  （实测某商品表里两个货号都写 163.23、平台是 163.23/188.88），用表里的价分档会与对话框行数对不上。
  **平台规则（2026-09-28）：活动价 ≤ 加速价×0.9 活动才有效**（活动是引流价，加速价没高出约
  11% 活动就失效）——故按本次对账确认报上的活动里该货号的最高申报价 ÷0.9 抬加速价；只认对账
  报上的活动，选了但被拒/跳过的没有生效价，拿它抬价会把加速价抬得虚高。某档上限低于要填的价时：
  还能退填「档内最高底价+1」就退填并注明**活动将失效**（用户定「接收活动失效」，照开）；连
  底价+1 都超上限才**整单中止不开**并如实报出是哪个档、上限多少、底价多少——绝不改填低价。

正式报名对账最多查询三轮，采用最后一轮按 SPU 查全的最新记录。历史基线不回填到当前结果：
本批必须有实际提交，且相对于完整基线出现新增记录、报名时间更新或从退出恢复，才计为本次报名成功。
同一活动多条记录按报名时间判断最新状态，时间不足或记录冲突则不确认。最新记录已退出、未知状态、
分页缺失、重复页或查询到其他 SPU 均不算成功。已标定的 1/3/4 为成功态，字符串状态码会归一化；
场次失败原因保留为提示，不否决已确认的报名成功。报名确认不等于平台最终展示价格已核验。

接口：`GET /activity/worklist?cloud_url=分享链接&sheet=工作表名`。不传 sheet 时只列工作表，
传入后返回列定义、原始单元格文本、SPU、价格及各行是否可选。读取在后台线程执行，不阻塞异步 Web 服务。
`POST /activity/batch` 使用 `cloud_url`、`sheet`、`spus`、`dry_run`、`live`、`selection`，拒绝本地文件路径；
`live` 空则沿用 `not dry_run`，显式给 `False` 即半程。`POST /activity/scan` 起识别作业，
`GET /activity/matrix` 回读当天矩阵，`POST /activity/batch/{job_id}/pause|skip` 控制暂停与逐格跳过。
事件流 `GET /activity/batch/{job_id}/events` 支持 `?since=N` 回放（刷新重连不丢事件）。

CLI：`python activity_manage.py --document "https://www.kdocs.cn/l/…" --sheet "工作表名" --spus "123 456"`。
默认只生成计划；`--execute` 保持现有半程行为，填价但不提交。
